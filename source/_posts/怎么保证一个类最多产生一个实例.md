# 问题的标注阐释

这个问题的标准名称是**单例模式**

我让AI生成了一段标准的描述:

> 在同一个 JVM 进程、同一个类加载器下，如何设计一个类，使得它在运行期最多只会被实例化一次，并且外界只能通过一个统一入口获取这个唯一实例？如果还要考虑多线程、反射、序列化等情况，又该如何防止产生第二个实例？

上课提到,所有问题都应该逐步思考,而不是直接获取答案 (这大概就是学习的乐趣所在)

那么接下来我就把我的思考过程写下来,给大家一些提示,逐步推导实现

# 外部禁止构造

首先需要实现的是这个,外部要是能随手`new`出一个新对象,显然直接任务失败

那么怎么才能防止外部的构造呢?

回忆一下类里定义的方法的几种属性,分别是`public`,`private`,`protected`

对了,`private`!

那么能否把构造函数搞成私有的,那么外面不久一直不能用了吗

经过搜索,发现这个语法上是成立的,这样第一步就实现了

# 外部的第一次构造

不知道你们大一学的怎么样,大一讲到的类的方法要是加上`static`就能被外界使用

通过这个方法就能实现操作类的实现与使用

我的想法是,搞个判断,比如我加一个新的`static bool is=0`,来判断,然后写一个`static void`来调用这次的构造,每次外界想要访问了,再判断是否需要构造

# 数据的存储

好问题,创建出来的这个对象,放在哪里,才能被所有的代码用上呢?

这么说来...,好像也只有一个地方可以放了,那就是在类的里面!

其实,这种写法是合法的:

```C++
class A{
	static A a;
}
```

所以我们可以把数据存在类里面,从而实现共享,然后再写几个函数,访问具体的数据就行了

# 几个步骤的时机

这个过程中,我们用到了:

**构造**,**判断**,**访问**

按照上面我的逻辑,我只要先构造,构造的前一秒判断,然后正常访问

**但是 ! ! !**

程序可能存在多线程,也就是有概率存在同时调用构造函数导致重复构造

所以要是我们真的只构造一次,也就是直接`static`构造,其他地方全部不写`new`,不就保证唯一性了吗?

**但是 ! ! !**

要是这个构造依赖于其他的信息,没法直接构造呢?

所以这两个方法有利有弊啊,但是想到这里,问题基本也结束了
# 总结(AI辅助)

实际上,最后我们想到的两个方案就是工程上使用的方法,分别叫做**饿汉式**和**懒加载**

## 饿汉式

```java
public final class Singleton {
    private static final Singleton INSTANCE = new Singleton();
    private Singleton() {}
    public static Singleton getInstance() {
        return INSTANCE;
    }
}
```

关键点：

- 构造器 `private`，外部不能 `new`。
- 静态实例 `private static final`，外部不能改引用。
- 类加 `final`，防止被继承后搞出别的实例。
- `getInstance()` 只返回，不再判断 `null`。
- 唯一性由 **JVM 类初始化只执行一次** 保证。

注意：饿汉式不是“程序一启动就创建”，而是“这个类第一次被主动使用时创建”。如果类还有其他静态方法，调用它们也可能触发实例创建。

## 懒加载

```java
private static volatile Singleton instance;
public static Singleton getInstance() {
    if (instance == null) {
        synchronized (Singleton.class) {
            if (instance == null) {
                instance = new Singleton();
            }
        }
    }
    return instance;
}
```

`volatile` 不能省。

静态内部类：

```java
private static class Holder {
    static final Singleton INSTANCE = new Singleton();
}
public static Singleton getInstance() {
    return Holder.INSTANCE;
}
```

其实这样也就差不多了,后面是更高级的写法,课程内部,这样应该是够用了
