## B

构造好题,正好可以用来练习构造题的关键思路:**理论下限,以及能否一定达到**

这题如果不仔细分析的话,很容易掉进二分的陷阱,然后只会往这个点所在的区域细分.

但是,试一试这个反例

```txt
8 8 1 3
```

发现先生成`2 6`更优

这就说明上面的思路是错误的了

### 分析理论下限

每一轮,必然能让最小单位变为原来的一半,所以理论上,如果最小单位是初始的$2^p$分之1,答案就是p

### 证明下限可达

每一轮,只要和初始存在的四个点交互就行了,其实试一试,发现在线段上,取到特定点其实也是可以这么做的.

所以这样代码就简单了,倒着枚举就行,$O(max(log\ A,log\ B))$

## C

概率交互典题

首先注意到这个交互方式很有意思,直接去问两两的关系筛选需要更多的次数,大概是2n

但是换一个角度考虑,大小关系好像可以理解为图?

这么一想,答案就接近了

每次往前走的时候,要是一直在增大,那么可以省下好多步数,因为这些一定是比起始点大的

当出现一个下降时,返回起点看一眼,因为此时有可能会比起始点小,需要确定是否换起始点

这个方案其实是非常优秀的,但是如果不采取随机化策略,依然能卡掉这个做法来到2n的交互次数

想到这里其实基本结束了,我当时就是想到了这里,不知道可以随机化优化交互

那么我们看看随机化后,这个方案的实际交互期望次数

### 期望交互次数

考虑连续上升次数,也就是一轮内处理掉的点数,因为多余的交互次数等于轮数

每次处理掉多于一个的概率是1,但是要是一轮只有一个,说明当前的比我小,直接往下就行

但是按照前面的规则,会回去再访问一次,还是需要1次

每次处理掉多于两个的概率也是`1`,多于三个的概率是`1/2!`,只要前两个上升就行

四个的话就是`1/3!`,以此类推,求和得到期望

因为这个概率只和三个数字大小有关,相当于几种顺序中的一种

求和得到
$$\sum Pr(L\geq K)=1+1+\sum_{i=1}\frac{1}{i!}=e$$
所以期望轮数为e,也就是平均每e个需要一次回去访问,这里所需的次数是$\frac{n}{e}$

然后万一更小了,还会得转移到新的下标,那就是取决于第一个是排名第几了

这个变化,**只会发生在新元素刷新“前缀最小值”时**。随机打乱后，第 \(i\) 个元素是前 \(i\) 个元素中最小值的概率为

$$\frac{1}{i}$$
因此，除第一个元素外，刷新最小值的期望次数是

$$\sum_{i=2}^{n}\frac1i=H_n-1=O(\log n)$$

当n=30000时,这个期望约为**10次**.而且,如果新元素直接从best出发就刷新了最小值,游标已经停在新最小值上,连这一次额外移动也不需要.


所以最后期望次数为
$$n+\frac ne+log\ n$$
刚好不超过

## D

作为本场的签到题,只要发现最大值必须是所有其他值的倍数,再加上必须有一个公共起点  

因为要是在同一起点,那么不用走,要不然一直往前,必然会到达最大值的位置,然后后面就不用动了  

否则必然得往前走,这样就和集卡的顺序有关了

### 参考代码

```C++
void solve(){
  ll n; cin>>n;
  ll maxn=0,maxp;
  vector<ll> a(n+1),b(n+1);
  for(int i=1;i<=n;i++){
    cin>>a[i]>>b[i];
    if(b[i]>maxn) maxn=b[i],maxp=a[i];
  }
  bool ans=1;
  for(int i=1;i<=n;i++)
    ans*=(maxn%b[i]==0&&(maxp-a[i]+b[i])%b[i]==0);
  cout<<(ans?"YES":"NO")<<endl;
}
```

## N

和前面的构造题思路类似,也是先想出理论上界,然后分析.

既然是构造题,那么先分析一下理论上界,应该是最小的n-2个数字的和,然后证明,

要是让一个数字取贡献两次显然不优,因为不然会导致一个比他大的数字无法贡献,

所以直接每次取最小值,把他相邻的左右两个连起来,构造出的就是答案.

### 参考代码

```C++
void solve(){
    ll n,ans=0; cin>>n;
    vector<pair<ll,ll>> a(n+1);
    vector<ll> l(n+1),r(n+1);
    vector<pair<pair<ll,ll>,ll>> res;
    for(int i=1;i<=n;i++) cin>>a[i].fs,a[i].sd=i;
    sort(a.begin()+1,a.end());
    for(int i=1;i<=n;i++) l[i]=i-1,r[i]=i+1;
    l[1]=n,r[n]=1;
    for(int i=1;i<=n-2;i++){
        auto[num,pos]=a[i];
        ans+=num;
        res.pb({{l[pos],pos},r[pos]});
        r[l[pos]]=r[pos];
        l[r[pos]]=l[pos];
    }
    cout<<ans<<endl;
    for(auto[x,y]:res) cout<<x.fs<<" "<<x.sd<<" "<<y<<endl;
}
```

## L

这题还是需要点思维的,但是既然选择了打表,那我就讲打表的正确性了,其他方案我就不管了

关键是想到切割段数等于操作次数+1,否则证明起来会很难受,当时队友应该是没有想到这个点的

然后队友是直接dp打表得到的,也不是不行,然后证明一下是对的就行

首先B<=D,那么直接切割成一堆B加一个余量,所以刚好是X/B向上取整-1次

然后是B>D,发现分界点是B,2B,2B+D,4B,4B+D,4B+2D,4B+3D,8D

因为当D增多的时候,每次显然是均分更优,但是D增多了会导致没法分配,所以需要划分更多的次数

因为为了减少划分次数,采用一定是分成B和B+D这样保证分成的段数少,也就是划分次数少

当D的多于段数大于2^a-1时,此时按照2^(a+1)B来划分更适合,所以代码其实极其的短

### 参考代码

```C++
void solve(){
  ll X,B,D; cin>>X>>B>>D;
  if(B<=D){cout<<(X+B-1)/B-1<<endl; return;}
  ll c=0; while((1ll<<c)*B+((1ll<<c)-1)*D<X) c++;
  cout<<(1ll<<c)-1+(max(0ll,X-(1ll<<c)*B)+D-1)/D<<endl;
}
```


## B

这是超级好题,对于我来说,比下面的K更难,更有价值

### 思路

这题的关键在于发现可以倒着dp,然后理解每次给两个的关系的作用.

首先发现不能贪,这个应该还是很好理解的,随便找点样例就能hack

队友当时想的是,每次把小恶魔定在最优的位置上,这样开始贪心

但是这是不一定的.

所以只能变成,维护当前时刻,当i时小恶魔时,最少的错误次数,也就是dp了

正着考虑发现,一旦这个人死亡,所有人都可以变为小恶魔

变成一个更新多个,不容易,正所谓正难则反,所以得反过来dp,这样变成多对一.

所以`c_i==0`时,`dp[a]`,`dp[b]`增1,因为他们按照要求本不应该是小恶魔

`c_i==1`时,其余增1,因为小恶魔应该出现在这两个里面

当有人复活时,相当于取后面所有人的最小值,然后再按照前面的规律更新

然后这样就能直接可持久化线段树了,但是可以更简单.

想想为什么题目要每次给两个,维护的关键就在这里

因为所有人除了这两位都+1等效于,搞一个tag+1,他们-1,这就是批量处理的思想,这样维护难度会大大降低

### 实现方式

其实最好写的方案是直接开个multiset,这个很无脑

但是追求时间复杂度的话,也可以开桶,效果差不多

这里我参考代码选择的是多重集合的方案

```C++
void solve(){
  ll n,m,add=0; cin>>n>>m;
  multiset<ll> s;
  vector<ll> a(n+1),b(n+1),c(n+1),d(n+1),f(n+1);
  for(int i=1;i<=m;i++) cin>>a[i]>>b[i]>>c[i]>>d[i];
  for(int i=1;i<=n-m;i++) s.insert(0);
  for(int i=m;i>=1;i--){
    f[d[i]]=*s.begin();
    s.insert(f[d[i]]);
    if(c[i]){
      add++;
      auto it=s.find(f[a[i]]);
      s.erase(it);
      it=s.find(f[b[i]]);
      s.erase(it);
      f[a[i]]--,f[b[i]]--;
      s.insert(f[a[i]]);
      s.insert(f[b[i]]);
    }
    else{
      auto it=s.find(f[a[i]]);
      s.erase(it);
      it=s.find(f[b[i]]);
      s.erase(it);
      f[a[i]]++,f[b[i]]++;
      s.insert(f[a[i]]);
      s.insert(f[b[i]]);
    }
  }
  cout<<*s.begin()+add<<endl;
}
```


## K

这个是我赛后补出来的,感觉比B简单,因为没有批量维护那个思路

这题的关键点是意识到这个序列是排列的作用.然后要把思路放在每次少一个会发生什么这个方向上
按照这个思路会十分容易思考.

### 思路

#### 考虑少掉一个

首先考虑少掉一个会发生什么.当去掉一个的时候,虽然少管了一行一列,但是都会被其他的车管住

| O   | -   | +   | +   |
| --- | --- | --- | --- |
| \|  |     | \|  | \|  |
| +   | -   | O   | +   |
| +   | -   | +   | O   |

所以只要看去掉的那个车的位置能否被其他车覆盖就行了,这时存在条件就很直观了

所以当存在abs(ai-a{i-1})为1时,必然能少掉一个

#### 考虑再少掉一个

然后考虑能否再少掉一个.也是同样因为排列,所以只要这个位置也同样被覆盖就行,但是,和上一个去掉的车,横竖的轨迹交集的位置,会变为空白(假设只看横竖)

所以得有其他“王”来管.因此此处确定一个车少掉后,看他的上下两行,观察其左右的控制范围,不会超过三列.检查这三个列内的数字就行,因为只有这里的数字可能满足要求

此处枚举的时间复杂度为3n,特判我写的有点屎

#### 再再少掉一个

最后考虑能否得到n-3,此时有9个点得靠“王”的方式管理,

这时,必须是中间有个点控制四个点,才能满足要求,这个枚举就不演示了,结论是下面这个

**经过枚举发现用来控制的车的位置关系必然形似样例2或者其对称**

#### 还能少掉一个点吗?

然后n-4一定不行,我尝试了没有解法.

因为从三的那个里面可以看出,中间必须有一个控制周围四个点,即使用这种方案控制更多的点,也没有解法,所以无解(也是枚举出来的)

最后写过模拟枚举三种情况就行了,O(n)

  ll minn=n;
  for(int i=1;i<=n;i++){
    if(i+6<=n){
      vector<ll> t={a[i],a[i+1],a[i+2],a[i+3],a[i+4],a[i+5],a[i+6]};
      sort(t.begin(),t.end());
      if(t[0]+1==t[1]&&t[0]+2==t[2]&&t[0]+3==t[3]&&
        t[0]+4==t[4]&&t[0]+5==t[5]&&t[0]+6==t[6]){
        if((a[i+2]==a[i]+4&&a[i+4]==a[i]+2&&a[i+6]==a[i]+6)||
          (a[i]==a[i+6]+6&&a[i+2]==a[i+6]+2&&a[i+4]==a[i+6]+4)){
            minn=n-3; break;
        }
      }
    }
    if((abs(a[i]-a[i-1])==1&&i-1>=1)||(abs(a[i]-a[i+1])==1&&i+1<=n)){
      minn=min(minn,n-1);
      set<ll> s;
      if(a[i-1]-1>=1&&i-1>=1) s.insert(a[i-1]-1);
      if(a[i-1]+1<=n&&i-1>=1) s.insert(a[i-1]+1);
      if(a[i+1]-1>=1&&i+1<=n) s.insert(a[i+1]-1);
      if(a[i+1]+1<=n&&i+1<=n) s.insert(a[i+1]+1);
      s.erase(a[i]);
      for(int x:s){
        ll p=pos[x];
        if((abs(a[p-1]-x)==1&p-1>=1&&a[p-1]!=a[i])||(abs(a[p+1]-x)==1&&p+1<=n&&a[p+1]!=a[i])){
          if((abs(a[i-1]-a[i]==1&&i-1>=1&&a[i-1]!=x)||(abs(a[i+1]-a[i])==1&&i+1<=n&&a[i+1]!=x)){
            if((abs(a[p-1]-a[i])==1&&p-1>=1)||(abs(a[p+1]-a[i])==1&&p+1<=n)){
              if((abs(a[i-1]-x)==1&&i-1>=1)||(abs(a[i+1]-x)==1&&i+1<=n)){
                minn=min(minn,n-2); break;
              }
            }
          }
        }
      }
    }
  }
  cout<<minn<<endl;
}
signed main(){
